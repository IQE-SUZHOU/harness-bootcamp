# Teach-back 讲稿（D5：交得出讲得清）

来源：D5 讲义要求「部件都好了，怎么交付」的答案是能一条命令验收 + 能五分钟讲清。
适用条件：验收演示、向新成员或业务方讲解本 harness 时读。
过期条件：五天递进改为持续演进、或 harness 结构不再四层时重写。

## 30 秒版

这个仓库的产品不是业务功能，是「让任何 agent 一读就能可靠干活」的最小外壳（mini harness）：
指令层告诉它该守什么规矩，状态层让它接得上班，范围层防止它跑偏，反馈层让它没法谎报完成。
一句话判据：`make teachback` 六 gate 全绿 = 交得出；本报告任何一节都讲不清 = 讲不得清。

## 3 分钟版：四层 × 五天链

| 层 | 工件 | 机制 | 入口 |
|----|------|------|------|
| 指令 | AGENTS.md（≤100 行目录页）+ docs/ 分专题 | 信噪比预算、中间迷失规避、规则带元数据 | `make contract` |
| 状态 | PROGRESS/DECISIONS/handoff + 运行态检查点 | 上班读状态、下班写交接、kill 后断点续跑 | `make start` `make resume` |
| 范围 | feature_list.json 状态机 | WIP=1、passing 必须绑定验证命令与证据 | `make test` |
| 反馈 | 六个可执行 gate + 负向自测 | 验证点=提交点、checker 只认 spec、报错附修复 | `make check` `make audit` |

五天递进，每天解前一天的遗留：
能跑起来 →(失忆)→ 断了能续上 →(恢复可信吗)→ 跑通才算完成 →(只能单点跑)→ 能并行能扩展 →(怎么交付)→ 交得出讲得清。

## 5 分钟演示脚本

1. `make init` —— 环境自描述，缺必需项直接失败不兜底。
2. `make teachback` —— 一键全量验收，报告从仓库实时生成。
3. 挑一个演示拆穿谎言：`make verify`（空口 done 被拒）或 `make loop`（坏支隔离、独立支不误伤）。
4. 打开 `PROGRESS.md` + `DECISIONS.md`：证明「为什么」也被持久化，新会话不必重新探索。

## 非确定性节点怎么判卷（D4 遗留的回答）

演示里期望值 = f(seed, spec) 可重算；真实业务节点（LLM 输出、CI 结果）不可重算，判卷降级为四级，
按强度自上而下选：

1. 属性断言/不变量：不问「输出等于什么」，问「输出必须满足什么」（schema 合法、引用路径存在、rc 与状态一致）。
2. 独立二次执行：同一任务跑两遍交叉比对，分歧即 fail——用冗余换确定性。
3. 抽样复核 + 人工评审：覆盖不到的部分显式标 blocked 并请示，不允许静默通过。
4. golden 快照：只允许用于已稳定且受控的输出；否则会把上次的错误固化成基线（本仓库已否决）。

## 验收出口清单

- 抽谁都能讲：按本稿 30 秒/3 分钟/5 分钟三档，任何新会话只凭仓库可复现
- 人人有业务提案：Top 3 表格换成自己的场景，标注选它标准
