# 全新会话测试（L03）

## 判据

开一个全新 agent 会话，只允许它读仓库，不许问人。五个基本问题与对应工件：

| 问题 | 依据文件 | 自动判定 |
|------|----------|----------|
| 这是什么系统？ | `AGENTS.md` 的项目概览 | `scripts/onboarding_quiz.py` 的 q1 |
| 怎么组织的？ | `docs/architecture.md` 模块表 | q2 |
| 怎么运行？ | `Makefile` 的 init target + `init.sh` | q3 |
| 怎么验证？ | `docs/verification.md` + `feature_list.json` 的 verification 字段 | q4 |
| 现在做到哪了？ | `PROGRESS.md` + `feature_list.json` + git | q5 |

`make quiz` 输出 n/5 与知识可见性缺口比例，答不上来的问题就是仓库地图上的空白。

## 为什么要做这个测试

agent 的输入只有三样：系统提示与任务描述、仓库里的文件内容、工具执行输出。
聊天历史、看板、口头约定、资深工程师的脑子里的规则，它一概看不见。
不写进仓库的信息等于不存在，每个新会话都只能靠猜——猜错是 bug，猜多浪费上下文，而且每轮都重猜一遍。

## 知识可见性缺口

1. 列出对项目工作重要的决策与约束（含口头约定、群里说过的规则）。
2. 逐条标注在仓库内还是仓库外。
3. 缺口 = 仓库外条目数 / 总条目数。目标是压到 10% 以下。

## 放置原则

- 知识靠近代码：模块约束放模块目录旁的短文档，50 行的就近文档胜过 500 页的过期大全。
- 发现成本优先：关键信息放 agent 最先看到的位置，别藏进十层目录。
- 最小但完备：删掉某条不影响决策质量的条目就不该存在；但五问必须有答案。
- 与代码一起更新：文档放对应模块目录，改代码时自然看到，过时文档比没有文档更危险。

## ACID 自检

| 原则 | 问自己 | 本仓库答案 |
|------|--------|-----------|
| 原子性 | 一个逻辑操作能否干净回滚 | 一个逻辑操作一次提交，未提交内容只在工作树 |
| 一致性 | 有没有"一致状态"的谓词 | `make check` rc=0 即一致；不一致拒绝开工 |
| 隔离性 | 多 agent 并发会不会互相踩 | 每人一个分支；状态文件按分支隔离；WIP=1 |
| 持久性 | 跨会话必需的知识是否落盘 | `PROGRESS.md` / `DECISIONS.md` / `feature_list.json` 全部 git 跟踪 |

## 定期重跑

每加一类工件后重跑 `make quiz`；分数下降说明新增内容没有接进路由，agent 读不到。
另需关注知识衰减率：单位时间内过时的条目比例，`make contract` 的死链检查只覆盖链接层面，
内容过时仍要靠人工审计。
